# ADR-0005: PostgreSQL + PostGIS for data and search; raw SQL for geo

**Status:** Accepted · **Date:** 2026-11-15

## Context

Search needs structured filters, geo queries (bbox, radius, nearest) and keyword search. OpenSearch adds cost and an extra data pipeline.

## Decision

- One **PostgreSQL 16 + PostGIS** database. `location` is `geography(Point,4326)` (GiST); `search_vector` is a generated `tsvector` (GIN); `pg_trgm` handles fuzzy matching; a partial index covers published listings.
- **Prisma** for ordinary CRUD; geography/tsvector columns are `Unsupported(...)` and accessed through **parameterised tagged-template SQL** in repositories (never string concatenation).
- Migrations are generated by `prisma migrate diff`, **reviewed by hand** (for generated columns and partial indexes), and applied with `migrate deploy`.

## Consequences

- ✅ One datastore, transactional consistency, no sync lag.
- ✅ The upgrade path to OpenSearch is isolated in `search-repository.ts`.
- ⚠️ `prisma migrate diff` always reports a harmless `DROP DEFAULT` on `search_vector`; documented in the schema.
